# Situaciones

Ocho situaciones del equipo del préstamo de portátiles. En cada una hay que decidir si compensa dar el trabajo a un agente aparte, no si se puede hacer.

| # | Situación |
|---|-----------|
| 1 | Antes de planificar la feature B hay que averiguar dónde se calculan hoy las reservas que se solapan. Hay que mirar muchos ficheros, pero el resultado cabe en cinco líneas. |
| 2 | Hay que escribir, con la coordinación TIC, la spec de la feature C. Las respuestas de la persona cambian las preguntas siguientes. |
| 3 | La feature D está implementada y los tests pasan. Quien la implementó (un agente) debería ahora comprobar que no hay *drift* respecto a la spec. |
| 4 | Hay que cambiar el texto del mensaje de error «Carro no encontrado» por «El carro no existe». |
| 5 | Tras fusionar cada feature hay que actualizar el `README.md` y la documentación de la API. Es un trabajo repetitivo que no necesita razonar mucho. |
| 6 | Las features C y D están aprobadas y cada una la hace una persona distinta. Se ha propuesto que cada una use un agente y trabajen a la vez. |
| 7 | Un agente va a escribir la spec de la feature E y, para ir más rápido, se le deja también aprobarla. |
| 8 | Se quiere analizar un módulo del centro que guarda datos personales del alumnado para reutilizar su lógica. El código no puede salir del centro. |
